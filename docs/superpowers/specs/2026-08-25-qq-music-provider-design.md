# QQ 音乐与网易云音乐双源整合设计

## 1. 背景与目标

Hydrogen Music 当前以内置的 `@neteasecloudmusicapienhanced/api` 作为主要在线音乐服务。前端 API、Pinia Store、播放器和详情组件大量沿用网易云音乐的响应结构。

本次改造将 `@sansenjian/qq-music-api` 整合进项目，使 QQ 音乐与网易云音乐作为两个独立在线音乐源共存，并对齐以下公共能力：

- 搜索歌曲、专辑、歌手、歌单和 MV。
- 浏览首页推荐、排行榜和新歌。
- 浏览歌单、专辑、歌手和 MV 详情。
- 播放歌曲、查看歌词、播放 MV 和下载歌曲。
- 在同一个播放队列中混合播放两个平台的歌曲。

网易云登录、喜欢、歌单管理、评论、云盘和私人 FM 等账号能力继续保留。QQ 音乐同时接入扫码登录和包 `2.5.0` 已提供的只读账号能力；上游未提供写接口的操作明确禁用，不模拟成功。

## 2. 非目标

本次不包含以下内容：

- QQ 音乐中上游包未提供的写操作，例如喜欢歌曲、收藏歌单、关注歌手和发表评论。
- 在 QQ 音乐与网易云音乐之间同步收藏、歌单或播放历史。
- 静默使用另一平台的同名歌曲替换不可播放资源。
- 将全部现有网易云 API 一次性重构成全新的 Provider 实现。
- 保证绕过平台版权、地区、会员或音质限制。

## 3. 核心设计原则

### 3.1 来源是资源身份的一部分

每个在线资源都必须携带 `source`。在线平台使用以下固定值：

- `netease`：网易云音乐。
- `qq`：QQ 音乐。

现有特殊来源继续保留，例如 `local` 和 `siren`。不带 `source` 的历史在线资源按 `netease` 处理，以兼容当前缓存、链接和播放状态。

歌曲、歌单、专辑、歌手和 MV 的唯一身份统一表示为：

```text
<source>:<id>
```

例如，`netease:123` 与 `qq:123` 是两个不同资源。QQ 歌曲应保留 API 播放所需的平台标识，例如 `songmid`。用于界面和队列的 `id` 不得丢失该标识，也不得假设所有平台 ID 都是数字。

### 3.2 后端路由隔离

现有网易云 API 保持 `/api/*` 行为不变。QQ 音乐 API 使用独立命名空间：

```text
/api/qq/*
```

`web-server.js` 在同一进程中启动静态文件服务、网易云音乐 API 和 QQ 音乐 API。开发环境由 Vite 以同样的路径规则代理。具体挂载方式以安装后读取到的 `@sansenjian/qq-music-api` 实际导出为准，不在未知包接口上预设不可验证的调用方式。

QQ 上游错误转换为稳定的 HTTP 状态和 JSON 错误结构，不触发网易云登录失效逻辑。未知 QQ 路由返回明确的 `404`。

### 3.3 渐进式 Provider 网关

前端新增统一音乐源网关，但保留现有网易云模块及其响应行为。网关只承接本次需要双源化的公共能力：

- 首页推荐、排行榜和新歌。
- 分类搜索。
- 歌单、专辑、歌手和 MV 详情。
- 歌曲播放地址、歌词、MV 地址和下载地址。

调用者传入 `source` 和资源参数。网关选择网易云或 QQ 实现，并返回现有页面可消费的规范结构。网易云适配器尽量透传当前数据；QQ 适配器负责字段归一化。账号 API 仍由现有网易云模块直接负责。

此方案避免在组件、Store 和播放器中散布 `if (source === 'qq')`，也避免为本次需求大范围重写已经稳定的网易云功能。

## 4. 规范数据模型

### 4.1 公共字段

所有双源资源至少包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string \| number` | 平台资源标识；QQ 资源允许字符串 ID |
| `source` | `netease \| qq` | 资源来源 |
| `sourceKey` | `string` | 由 `source:id` 生成的稳定身份键 |
| `name` | `string` | 展示名称 |

`sourceKey` 用于列表 `key`、队列去重、当前歌曲比较、缓存索引、歌词偏移键和选择状态。业务请求仍使用原始 `id` 或 QQ API 所需的平台标识。

### 4.2 歌曲

QQ 歌曲适配为项目现有歌曲结构，至少提供：

- `id`、`source`、`sourceKey` 和可选 `songmid`。
- `name`、`ar`（歌手数组）、`al`（专辑对象）、`dt`（毫秒时长）。
- 封面、版权或可播放状态，以及 Provider 原始数据中解析播放地址所需的最小元数据。

不得把完整无界的上游响应复制进持久化播放队列。只保留重建播放请求所需的字段。

### 4.3 歌单、专辑、歌手和 MV

QQ 资源分别映射到现有组件依赖的结构：

- 歌单：名称、封面、创建者、简介、曲目数、播放数和歌曲列表。
- 专辑：名称、封面、歌手、简介、发布时间和歌曲列表。
- 歌手：名称、头像、简介、热门歌曲、专辑和 MV。
- MV：名称、封面、歌手、时长、播放数、详情和可用清晰度地址。

缺失的非关键展示字段使用空字符串、空数组或 `0`，不伪造平台数据。关键字段缺失导致资源无法使用时，适配器返回可识别错误。

## 5. 用户界面与导航

### 5.1 首页音乐源

首页增加“网易云音乐 / QQ 音乐”来源切换。默认值为 `netease`，用户选择持久化到现有设置体系。切换来源后，推荐歌单、排行榜和新歌同步重新加载。

若 QQ API 缺少某个首页能力，对应区块显示可恢复的加载提示或不展示内容，不使用网易云数据冒充 QQ 结果。一个区块失败不阻断其他区块。

### 5.2 搜索来源

搜索页顶部增加独立来源切换，默认 `netease`。搜索来源不强制跟随首页来源，也不要求持久化。

搜索覆盖歌曲、专辑、歌手、歌单和 MV。切换来源或关键词后生成新的请求令牌；旧请求完成时不得覆盖当前来源的结果。搜索结果中的每个资源都带 `source`。

### 5.3 详情路由

现有详情路径保持不变，通过查询参数保存来源：

```text
/mymusic/playlist/:id?source=qq
/mymusic/album/:id?source=qq
/mymusic/artist/:id?source=qq
```

不带 `source` 时按 `netease` 处理。路由加载、详情缓存、滚动位置缓存和路由复用判断都必须同时考虑 `source` 与 `id`。

QQ MV 详情遵循项目实际采用的 MV 路由方式；若现有 MV 通过弹层打开，则在弹层载荷中携带 `source`，不为满足形式一致性额外增加页面。

## 6. 播放、歌词、MV 与下载

### 6.1 混合播放队列

播放队列允许网易云与 QQ 歌曲混合存在。以下逻辑必须从仅比较 `id` 改为比较 `sourceKey`：

- 当前歌曲与列表高亮。
- 加入队列、下一首播放和队列去重。
- 播放索引定位。
- 歌词状态、歌词偏移和媒体会话更新。
- 下载选择和上下文菜单选中项。

本地歌曲与塞壬歌曲沿用现有特殊分支，但统一身份工具需要兼容它们。

### 6.2 播放地址与音质降级

播放器根据歌曲 `source` 调用对应 Provider。QQ Provider 使用歌曲的平台标识解析播放地址，并把项目现有音质偏好映射到 QQ API 的可用档位。

目标音质不可用时，从高到低尝试不高于目标偏好的可用音质。成功响应必须包含最终 URL、实际音质和必要的文件信息。全部档位不可用时返回明确的不可播放错误。

不得在 QQ 播放失败时自动搜索网易云同名歌曲。这样可以避免错误版本、错误演唱者、版权差异和用户无感知的跨平台替换。

### 6.3 歌词

Provider 统一返回项目现有歌词载荷：

- `lrc`：原文歌词。
- `tlyric`：翻译歌词。
- `romalrc`：罗马音歌词。

QQ 未提供的附加歌词使用空内容。原文歌词缺失时沿用“暂无歌词”体验。QQ 歌曲不进入当前基于网易云搜索的歌词回退流程，除非未来有单独确认的跨平台歌词匹配设计。

### 6.4 MV

QQ MV 适配器返回详情与可用清晰度地址。用户选择的清晰度不可用时，可降级到较低的实际可用清晰度，并在界面状态中保留实际结果。没有任何可用地址时显示明确错误。

### 6.5 下载

下载继续复用现有媒体 URL 和保存流程。下载前通过资源来源解析 URL，文件元数据从规范歌曲模型获取。QQ API 返回的临时 URL 只用于当前下载任务，不持久化为长期可用地址。

## 7. 账号能力与会话隔离

网易云资源保留当前账号操作。QQ 账号支持扫码登录、会话恢复和包 `2.5.0` 提供的只读数据查询。QQ 资源不显示或禁用以下上游未提供写接口的操作：

- 喜欢或取消喜欢。
- 添加到网易云歌单、从网易云歌单删除。
- 收藏歌单、专辑、歌手或 MV。
- 评论、回复和点赞评论。
- 云盘、私人 FM 和账号推荐历史相关操作。

界面可用性由集中式能力判断函数决定，例如 `supportsAccountAction(resource, action)`。不得仅在点击后依赖接口失败来表达“不支持”。

QQ 歌曲仍可执行与平台账号无关的播放、下一首、下载、查看专辑和查看歌手操作。

### 7.1 QQ 扫码登录

登录页提供网易云音乐与 QQ 音乐平台切换。QQ 仅提供扫码登录：前端请求 `/api/qq/getQQLoginQr` 获取二维码和本次 `qrsig`，轮询 `/api/qq/checkQQLoginQr` 并传递 `ptqrtoken` 与 `qrsig`。登录成功后由 QQ API 包保存 Cookie，服务端只向前端返回脱敏的 `loggedIn`、`uin`、昵称和头像。

QQ Cookie 不进入 Pinia 持久化、本地存储、URL、日志或前端响应。QQ API 的会话状态保留在服务端；应用启动时通过 `/api/qq/user/getCookie` 或等价状态端点恢复。退出 QQ 时清除 QQ API 的本地 Cookie 和 QQ Store，不清除网易云 Cookie、网易云 Store 或播放队列。两个平台允许同时登录。

### 7.2 QQ 账号数据

“我的音乐”提供 QQ 来源切换，展示以下已由包提供的只读数据：喜欢的歌曲、创建的歌单、收藏的歌单、收藏的专辑、关注歌手和收藏 MV。QQ 账号详情页可展示用户资料、好友/粉丝、VIP、勋章、听歌日历、音乐基因和不喜欢列表。

各账号区块独立加载。某个 QQ 区块失败不阻塞其他区块；会话失效时只清除 QQ 会话并提示重新扫码。

## 8. 状态、缓存与兼容性

- 首页来源使用现有设置 schema 持久化，非法值回退到 `netease`。
- 搜索 Store 同时保存当前来源、请求令牌和结果，避免跨来源竞态。
- 详情 Store 的索引与 hydration 键改用 `sourceKey`。
- 旧队列、旧缓存和旧链接缺少 `source` 时迁移为 `netease`。
- 路由、组件属性和工具函数继续接受旧式数字 ID，但内部身份比较统一走辅助函数。
- QQ 请求使用独立 Axios 客户端或独立适配器，不复用网易云 Cookie 注入、登录失效检测和 NCM IPC 就绪逻辑。

## 9. 错误处理

错误按以下层级处理：

1. QQ 服务未启动或依赖加载失败：服务启动日志给出明确错误，QQ 请求返回服务不可用；网易云服务仍可继续运行。
2. QQ 上游接口失败：统一转换错误，不触发网易云自动退出。
3. 单个首页区块失败：仅影响该区块，允许重试。
4. 搜索失败：保留关键词和当前来源，显示重试提示，不展示上一来源结果。
5. 详情关键字段缺失：停止进入不可用详情并提示加载失败。
6. 播放、MV 或下载无可用地址：显示版权、会员、地区或上游不可用的通用说明，不承诺无法从 API 判定的具体原因。
7. 二维码过期、扫码取消、轮询错误或 QQ 风控：只更新 QQ 登录状态，不触发网易云自动退出。
8. QQ API 返回 `401`、`403` 或明确未登录业务码：服务端清除 QQ 会话并返回 `loggedIn: false`；前端清除 QQ 账号资料并提示重新扫码。

日志不得输出 Cookie、鉴权令牌、完整临时媒体 URL 或其他敏感信息。

## 10. 测试策略

### 10.1 单元与契约测试

新增测试至少覆盖：

- QQ 歌曲、歌单、专辑、歌手、MV 和歌词响应归一化。
- QQ 扫码登录二维码状态机、会话恢复和退出清理。
- `sourceKey` 生成、旧数据默认来源和相同 ID 的跨平台隔离。
- 路由来源读取与默认值。
- 首页来源设置的校验与持久化。
- 音质和 MV 清晰度降级。
- QQ 账号操作能力判断。
- QQ 用户资料、喜欢歌曲、歌单、收藏专辑、关注歌手和收藏 MV 的只读映射。
- QQ 会话失效只影响 QQ，不清除网易云账号或播放队列。
- Cookie 不出现在前端响应、持久化状态、fixture 和日志。
- 上游缺失字段和错误响应。

适配器测试使用脱敏、最小化的响应 fixture。fixture 以安装后的包实际响应为准，不凭猜测编写。

### 10.2 Store 与网关测试

覆盖以下行为：

- 首页按选定来源分发请求。
- 搜索切换来源后忽略旧请求。
- 两个平台的搜索分类结果均进入规范结构。
- 详情请求同时按 `source` 和 `id` 分发与缓存。
- 同 ID 的网易云歌曲与 QQ 歌曲可以同时进入队列并分别播放。

### 10.3 服务端测试

覆盖以下行为：

- `/api/*` 网易云路由与 `/api/qq/*` QQ 路由同时可用。
- 未知 QQ 路由返回 `404`。
- QQ 上游错误转换为稳定错误结构。
- 播放 URL 与歌词端点返回适配器所需数据。
- QQ 服务初始化失败不应破坏网易云服务。

### 10.4 完整验证

交付前运行：

- 所有新增测试。
- 项目已有的 `test:selection-animation` 回归脚本。
- 生产构建。
- 服务端双命名空间的最小烟雾测试。

若真实 QQ 上游受网络、版权或地区影响，自动测试以适配器契约为主，烟雾测试记录当时的实际可用状态，不把外部服务不稳定误报为本地逻辑通过。

README 更新以下内容：

- 项目已支持网易云音乐与 QQ 音乐双源。
- 安装与启动方式。

- QQ 音乐公共能力和账号能力限制。
- 版权、会员、地区、临时 URL 与上游服务可用性说明。

实现阶段先安装并检查 `@sansenjian/qq-music-api` 的实际版本、导出、路由和响应，再确定服务端挂载和 fixture。若包的真实能力无法覆盖本设计中的某一公共功能，应先报告具体缺口并缩小对应功能，而不是编造数据或绕过平台限制。

## 12. 实施顺序

1. 安装并验证 QQ API 包，记录真实路由与响应。
2. 先为资源身份、数据适配和 Provider 契约编写失败测试。
3. 实现服务端 QQ 命名空间和前端独立请求客户端。
4. 实现规范模型、QQ 适配器与 Provider 网关。
5. 接入搜索和详情，再接入首页。
6. 接入混合播放队列、歌词、MV 和下载。
7. 集中处理账号能力隔离与旧状态兼容。
8. 接入 QQ 扫码登录、会话恢复、只读账号数据和独立退出。
9. 更新 README，运行完整验证。
